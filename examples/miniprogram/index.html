小程序设计规范：从 5 个移动端站推导

不要凭空造。这 5 个站都是专门做移动端界面参考的，它们页面上的按钮尺寸、字号、间距就是真实产品在用的值。

5 个参考站 324 个组件样本 按小程序平台约束收敛

推导依据

每个关键决策都能追溯到实测数据。

  • 触屏目标 44px 实测 5 个站共 34 个按钮/输入框，高度中位 38px，44px 是出现最多的单值（6 次）。微信官方建议热区 ≥44×44px，取 44。
  • 间距基准 8px 实测间距 top4 是 20/8/16/24px（439/329/226/209 次）。只有 8px 能整除全部主流值，20px 无法构成网格。
  • 正文字号 16px 实测 16px 出现 690 次，是第二名（14px，108 次）的 6.4 倍。绝对主导。
  • 圆角 8/16/24/full 实测 top 是 30%(263)、8px(85)、20px(77)、24px(49)、32px(33)。30% 是相对值不通用，取整成四档。
  • 主色 #07C160 5 个参考站里有 2 个没有主色，其余的也不统一。所以不用它们的，取微信品牌绿作为默认。

要说明白：这 5 个站是「在桌面浏览器上看移动端截图」的网站，不是小程序本身。它们的按钮尺寸可信（因为展示的是真实 App 界面），但颜色和字体是它们自己网站的，不能代表小程序。

所以：尺寸和间距用实测值，颜色和字体按平台约束重定。

为什么正文是 16px：实测 690 次，是第二名（14px）的 6.4 倍。

为什么输入框必须 16px：iOS Safari 在字号小于 16px 的输入框聚焦时会自动放大整个页面。这是硬约束，不是审美选择。

代码

两个文件，直接放进小程序项目。

theme.wxss · 变量定义 
page {
  --color-primary: #07C160;
  --color-bg-page: #F7F7F7;
  --color-text: #1A1A1A;
  --color-text-2: #888888;

  --space-sm: 16rpx;   /* 8px */
  --space-md: 32rpx;   /* 16px */
  --space-lg: 48rpx;   /* 24px */

  --radius-sm: 16rpx;  /* 8px */
  --radius-md: 32rpx;  /* 16px */
  --radius-full: 9999rpx;

  --font-body: 32rpx;  /* 16px */
  --btn-height: 88rpx; /* 44px */
}
app.wxss · 组件样式 
.btn {
  display: flex;
  align-items: center;
  justify-content: center;
  height: var(--btn-height);
  border-radius: var(--radius-full);
  font-size: var(--font-body);
  font-weight: 500;
}

.btn-primary {
  background: var(--color-primary);
  color: #fff;
}

.btn::after { border: none; }

/* 底部 tabBar 必须处理安全区 */
.tabbar {
  height: 100rpx;
  padding-bottom: env(safe-area-inset-bottom);
}

必须遵守的约束

  • 热区 ≥44px微信官方建议。小于这个值手指点不准。
  • 输入框 ≥16px否则 iOS 会自动放大页面。
  • 处理安全区底部固定元素要加 env(safe-area-inset-bottom)，否则被 iPhone 横条挡住。
  • 导航栏动态算用 wx.getMenuButtonBoundingClientRect() 计算，不要写死 44px。
  • 不用自定义字体小程序不支持 @font-face 加载外部字体文件。
  • 少用 box-shadow小程序渲染层性能有限，用背景色对比代替阴影。
  • 不要依赖 hover触屏没有 hover 状态，只用 :active。
